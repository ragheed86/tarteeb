# دستور مشروع ترتيب (Tarteeb) — Constitution

**النطاق**: نظام إدارة أعمال (ERP) لشركة تنظيم منازل في الرياض.
**آخر تحديث**: 2026-08-23

## 1. المكدّس التقني (ثابت، لا يُغيَّر بدون قرار صريح)

- **Next.js 16 (App Router)** — JavaScript عادي (`.js`/`.jsx`)، **بدون TypeScript**. لا تُدخل ملفات `.ts`/`.tsx` جديدة.
- **Supabase** (Postgres + Auth) — مصدر الحقيقة الوحيد للبيانات. المشروع الصحيح: `yvxequegdyrhjghprnya`.
  لا يوجد أي تخزين محلي دائم (localStorage/IndexedDB) للبيانات التشغيلية — كل شيء يُقرأ ويُكتب مباشرة عبر `src/lib/data.js`.
- **MapLibre GL JS** لأي احتياج خرائط (لا Google Maps، لا Mapbox المدفوع).
- **Vercel** للنشر — مشروع `tarteeb-six` تحت scope `tarteeb`.
- لا مكتبات UI ثقيلة إضافية (لا MUI، لا Tailwind) — نظام تصميم مخصّص بـCSS عادي في `src/app/globals.css`.

## 2. قواعد اللغة والتنسيق (غير قابلة للتفاوض)

- **كل نص الواجهة بالعربية**. لا نصوص إنجليزية ظاهرة للمستخدم إلا الأكواد التقنية (barcode، رموز URL).
- **كل الأرقام لاتينية دائماً** (`0-9`)، حتى داخل نص عربي — عبر `Intl.NumberFormat('en-US')` (`fmtNum`, `fmtMoney` في `src/lib/format.js`). ممنوع استخدام أرقام هندية (`٠١٢...`).
- **التواريخ**: `Intl.DateTimeFormat('ar-SA-u-nu-latn', ...)` — عربي بأرقام لاتينية.
- **رمز العملة**: الحرف الرسمي الجديد `⃁` (U+20C1)، وليس `ر.س` أو `SAR`. الخط مُستضاف ذاتياً (`public/fonts/saudi-riyal-*.woff2`) بـ`unicode-range` مقتصر على هذا الحرف فقط — **لا تُزل** قواعد `@font-face` هذي من `globals.css`.
- **الاتجاه RTL** بالكامل (`dir="rtl"` على `<html>`). استخدم خصائص CSS المنطقية (`margin-inline-start`, `inset-inline-end`) لا الفيزيائية (`margin-left`) إلا في حالات مقصودة موثّقة (مثل عمود الإجراءات بالجداول).

## 3. قواعد البيانات (Data Layer)

- كل الوصول لقاعدة البيانات يمرّ عبر `src/lib/data.js` — لا استدعاء `supabase` مباشرة من مكوّنات الصفحات.
- **الموقع الجغرافي يُخزَّن على العميل فقط** (`clients.district`)؛ المشاريع والفواتير *ترث* الموقع عبر `client_id` — لا تكرّر تخزين الحي بجداول أخرى.
- **بنود التكلفة (`project_costs`)**: نوعان يتعايشان بنفس الجدول ويجب عدم الخلط بينهما:
  - *مُدارة* (managed): تأتي من "الجدول التقديري" (`kind='labor'` بـ`label` من `{عمالة, إشراف}`، أو `kind∈{materials,transport,other}` بـ`label=null`). تُستبدل بالكامل عند كل حفظ عبر `saveProjectCosts`.
  - *حرة* (ad-hoc): يضيفها المستخدم يدوياً (أي `kind`/`label` آخر). **لا تُحذف أو تُستبدل تلقائياً أبداً** — التمييز عبر `splitManagedCosts()` في `data.js`، ويجب استخدامها لا إعادة كتابة المنطق بمكان آخر.
- **enum بقاعدة البيانات يجب أن يطابق خيارات الواجهة دائماً** — إذا أُضيف خيار جديد بـ`<select>` (مثل مصدر عميل)، تحقّق أولاً أن قيمته موجودة فعلياً بـenum قاعدة البيانات قبل الاعتماد على نجاح الحفظ.
- **لا بيانات وهمية (mock/demo) بالكود** — أي رقم أو قائمة تظهر بالواجهة يجب أن تأتي من استعلام حقيقي. إذا كانت بيانات فعلية غير متوفرة بعد، اعرض حالة "فارغ" (`Empty` من `src/app/ui.jsx`) لا رقماً مصطنعاً.

## 4. مطابقة الأحياء (Heatmap)

- مفتاح المطابقة بين بيانات العملاء وGeoJSON يمرّ حصراً عبر `src/lib/heatmap/normalize.js` (`districtMatchKey`). **لا تُنشئ منطق تطبيع مواز بمكان آخر** — استورد من هذا الملف دائماً (بما إن المشروع JS عادي، لا حاجة لتكرار الكود بين السكربت ووقت التشغيل كما بمشاريع TS).
- أي حي غير مطابق بالفهرس يُتجاهل بصمت بالخريطة (لا خطأ) — هذا سلوك مقصود، ليس خللاً.

## 5. رفع الملفات

- Supabase Storage مفعّل. حاوية صور المنتجات فقط عامة لأنها أصول عرض عامة؛ مستندات الجهات، صور الموظفين، وسائط المشاريع ولوحة المعلومات، ومرفقات التكاليف حاويات خاصة.
- خزّن مسار الكائن الدائم (`*_path`) في قاعدة البيانات، وأنشئ رابطاً موقّعاً محدود الصلاحية عند القراءة. لا تخزّن الرابط الموقّع لأنه ينتهي.
- كل حاوية يجب أن تحدد الحد الأقصى للحجم وأنواع MIME المسموحة، وتستخدم سياسات RLS مرتبطة بصلاحية الشاشة المناسبة.

## 6. سير النشر (Deploy Workflow)

بعد أي تعديل كود:
1. `npm run build` محلياً (يجب أن ينجح بدون أخطاء — تجاهل تحذيرات ESLint إن وُجدت، البناء يتخطاها فعلياً).
2. `git add` للملفات المقصودة فقط (لا `-A` عشوائي).
3. `git commit` برسالة conventional (`feat:`, `fix:`, `chore:`...).
4. `git push origin main`.
5. `npx vercel --prod --yes --scope tarteeb`.
6. تحقّق حي: `curl` على الصفحات المتأثرة + أي تحقق بيانات عبر Supabase MCP إن أمكن.

لا تعتمد على معاينة متصفح تفاعلية محلية بهذه البيئة — أداة تشغيل السيرفر المحلي غير موثوقة هنا؛ الاعتماد الأساسي للتحقق هو البناء المحلي + الفحص المباشر للموقع المنشور.

## 7. حدود صلاحية التنفيذ

- أي حذف بيانات أو ملفات جماعي (مثل تنظيف مجلدات قديمة، حذف صفوف قاعدة بيانات بدون شرط) يتطلب تأكيداً صريحاً من المستخدم قبل التنفيذ — لا تفترض الموافقة من طلب عام.
- أي تثبيت مكتبة/أصل من مصدر خارجي (خط، صورة، بيانات جغرافية) لم يُسمِّه المستخدم صراحة، يُذكر مصدره ورخصته للمستخدم قبل إدراجه بالمشروع الحي.
