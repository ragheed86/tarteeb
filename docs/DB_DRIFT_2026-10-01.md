- **CRM-AUD-02:** دوال القروض الداخلية الثلاث: `EXECUTE` = false لـ anon وauthenticated (بعد `20261001110000`).
- **فحص Supabase الأمني (Advisors)** بعد تغييرات اليوم: لا ملاحظات جديدة. المتبقي قديم ومعروف:
  - 23 دالة `SECURITY DEFINER` يستدعيها المستخدم المسجّل، وهي مقصودة لأنها تتحقق من الصلاحية داخلها.
  - `pg_net` في مخطط public.

- **حاويات الملفات:** كلها خاصة بصلاحية الوحدة، ما عدا `product-images` العامة عن قصد. ولكل منها حد للحجم والنوع.

## الإصلاح المقترح (يحتاج جهاز رغيد)

لجلب الهجرات الـ36 كملفات مطابقة حرفياً لما في الإنتاج:

```bash
cd tarteeb
npx supabase link --project-ref yvxequegdyrhjghprnya
npx supabase migration fetch      # ينزّل الهجرات من سجل الإنتاج إلى supabase/migrations
git add supabase/migrations && git commit -m "chore(db): مزامنة سجل الهجرات مع الإنتاج"
```

بعدها يصبح الريبو مصدراً كاملاً لإعادة بناء القاعدة (مثلاً لبيئة الاختبار في CRM-AUD-09).
لم يُنفَّذ هذا من هنا لأنه يحتاج كلمة مرور قاعدة البيانات، ونسخ 71 ألف حرف من SQL يدوياً عرضة للخطأ.
